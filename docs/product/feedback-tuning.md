# 고객 피드백 → 붕봇 보정 기획

> 상태: MVP 구현 완료 (2026-11-06) · 구현 계획: `docs/superpowers/plans/2026-11-06-customer-feedback-tuning.md`

## 1. 한 줄 정의
손님이 "좀 탔어요" 한마디 남기면, 여러 손님 의견을 모아 **붕봇 레시피를 조금씩 맞춰 가는** 기능.
(사장님이 단골 반응 보고 불 세기를 조절하던 걸 데이터로 하는 것)

## 2. 배경 / 문제
- 로봇은 정해진 값(굽기 시간·앙금 양)으로만 굽는다. 반죽 상태·날씨·틀 온도가 바뀌어도 스스로 모른다.
- 사장님은 계속 옆에서 맛을 볼 수 없다. 손님 반응이 가장 빠른 센서다.
- 별점은 "별로였다"만 알려 주고 **어느 쪽으로 고칠지**는 알려 주지 않는다.

## 3. 목표 / 비목표
| 목표 | 비목표 |
|---|---|
| 픽업한 손님에게 3초 안에 끝나는 피드백 받기 | 자유 텍스트 리뷰, 사진, 공개 별점 |
| 피드백을 로봇 파라미터 보정 방향으로 바꾸기 | 로봇 완전 자동 학습 |
| 사장님이 근거를 보고 한 번에 승인 | 손님별 맞춤 굽기 (개인화) |

## 4. 등장인물과 흐름
| 누가 | 언제 | 무엇을 |
|---|---|---|
| 직원 | 손님에게 봉투 건넴 | 주문판 **픽업 완료** 누름 |
| 손님 | 픽업 3분 뒤 (먹어 본 뒤) | bottom sheet 자동 등장: 3문항 고르고 **보내기** 또는 **나중에** |
| 손님 | 3분 전이라도 이미 먹었으면 | 주문 화면 **맛 평가하기** 카드로 바로 열기 |
| 손님 | "나중에" 이후 언제든 | 주문 내역 **맛 평가 남기기** 링크로 다시 열기 |
| 사장님 | 오늘 현황 탭 | 피드백 보정 카드에서 추천 **적용 / 무시** |
| 붕봇 | 다음 주문부터 | 바뀐 값으로 굽기 (실제 전송은 로봇 연동 단계) |

## 5. 손님 화면 (bottom sheet)
**원칙: 생각 없이 탭 3번.** 필수 항목 없음, 하나만 골라도 보내기 가능.

| 문항 | -2 | -1 | 0 | +1 | +2 | 고치는 값 |
|---|---|---|---|---|---|---|
| 굽기 정도 | 덜 익음 | 조금 덜 | **딱 좋아요** | 조금 더 | 탔어요 | 굽기 시간 |
| 속 양 (맛별: 팥앙금 양 · 커스터드 양 · 초코크림 양) | 너무 적음 | 조금 적음 | **딱 좋아요** | 조금 많음 | 너무 많음 | 해당 맛 앙금 g |
| 바삭함 | 눅눅해요 | 조금 눅눅 | **딱 좋아요** | 조금 딱딱 | 너무 딱딱 | 마무리 굽기 시간 |

- **양극 척도**를 쓰는 이유: 가운데가 정답이라 "어느 쪽으로, 얼마나"가 바로 나온다.
- "탄 정도"는 따로 두지 않음 → 굽기 +2. 같은 값(굽기 시간)을 두 문항이 건드리면 해석이 충돌.
- **먹은 뒤에 묻는다**: 고객 앱이 픽업 완료를 처음 본 시각(`boong:pickup-seen`)부터 3분(`FEEDBACK_DELAY_MS`) 뒤 자동 등장.
- 한 주문당 1회. 보내면 끝. "나중에"는 자동 등장만 멈추고, 주문 화면·주문 내역에서 직접 남길 수 있음.

## 6. 집계 규칙
1. **중앙값** (평균 X): 장난으로 "탔어요" 몇 개 눌러도 안 흔들린다.
2. **가중치**
   - 최신성: 3일마다 영향력 절반 → 지난주 반죽 얘기가 오늘 보정을 끌고 가지 않음
   - 단골: 주문 많을수록 최대 2배 → 자주 먹는 사람이 맛 변화를 잘 안다
3. **최소 표본 5건** 전엔 추천 안 함.
4. 중앙값이 ±0.5 안이면 **유지**.
5. 보정 적용 후엔 **그 이후 피드백만** 센다 (바꾸기 전 맛에 대한 의견이므로).

## 7. 로봇 반영 정책 (안전)
- 자동 반영 없음. **사장님 승인** 후에만 바뀜.
- 한 번에 **1스텝**만 (굽기 ±5초, 마무리 ±3초, 앙금 ±2g).
- 범위 밖으로 못 감 (굽기 60~150초 등). 끝에 닿으면 "조정 범위 끝"으로 알려 사람 점검 유도.
- 모든 변경은 이력으로 남음 → 되돌릴 근거.

## 8. 사장님 화면 (피드백 보정 카드)
| 상태 | 표시 | 버튼 |
|---|---|---|
| 모으는 중 | 현재값 · "피드백 모으는 중 3/5" | 없음 |
| 유지 | 현재값 · "딱 좋아요 · 유지" | 없음 |
| 추천 | "90초 → 85초" · `"탔어요" 쪽 · 중앙값 +2 · 5건` | 무시 / 적용 |
| 범위 끝 | 현재값 · "조정 범위 끝이에요" | 없음 |

## 9. 성공 지표 (측정 계획)
- 응답률: 픽업 주문 중 피드백 보낸 비율 (목표 30%+)
- "딱 좋아요" 비율이 보정 후 올라가는가 (항목별)
- 추천 → 적용 비율 (사장님이 추천을 믿는가)
- 범위 끝 도달 횟수 (레시피 자체 문제 신호)
