# 붕붕 붕어빵 MVP 구현 계획 (React 웹)

화면 설계: [../../product/screen-plan.md](../../product/screen-plan.md)

## 기술 스택

| 항목 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + React + TypeScript | 가장 빠른 셋업, 모바일 웹 |
| 라우팅 | react-router-dom | 화면 5개 + 로그인 가드 |
| 상태 | React Context + useReducer | 장바구니·로그인 정도라 상태 라이브러리 불필요 |
| 스타일 | 일반 CSS + CSS 변수 토큰 | 의존성 없음 |
| 폰트 | Google Fonts (Jua 제목 / Gowun Dodum 본문) | 둥근 한글 |
| 일러스트 | 인라인 SVG 컴포넌트 (붕어빵·붕봇·할매·할배) | 이미지 생성 없이 바로 시작, 나중에 클레이 PNG로 교체 가능 |
| 저장 | localStorage (`orderService`로 감쌈) | MVP, 서버 교체 지점 1곳 |
| 테스트 | Vitest + Testing Library + jsdom | 도메인 로직 + 핵심 흐름 |

추가 의존성: `react`, `react-dom`, `react-router-dom` / dev: `vite`, `@vitejs/plugin-react`, `typescript`, `vitest`, `@testing-library/react`, `@testing-library/user-event`, `jsdom`.
(7일 최소 배포일 정책 그대로 적용)

## 3D 애니메이션 (추가 요청)

레퍼런스: 말랑한 클레이 3D 캐릭터 + 파스텔 그라데이션 배경 (토스 걷기 화면, 별 캐릭터).

### 상태별 장면

| 상태 | 화면 | 장면 |
|---|---|---|
| 입장 | S1 로그인 | 할매·할배 손 흔들기, 붕어빵이 통통 튐 |
| 대기 중 | S2 메뉴 | 붕봇 살랑살랑 대기, 눈 깜빡, 틀에서 김 모락모락 |
| 담는 중 | S2 + 버튼 | 붕어빵이 봉투로 퐁 떨어짐 |
| 주문하는 중 | S3 제출 | 붕봇이 주문서 받아 고개 끄덕 |
| 반죽 → 속 → 굽기 → 포장 | S4 | 로봇팔이 단계별로 움직임, 틀 뒤집기, 할배가 봉투에 담기 |
| 픽업 대기 | S4 | 붕어빵이 봉투에서 고개 내밀고 반짝 |

### 구현 방식 (결정 필요)

- **A. 3D 렌더 이미지 + CSS/모션 애니메이션** — 클레이 캐릭터를 이미지로 만들고(AI 생성 또는 직접 제작) 튀기·흔들기·김 효과는 코드로 줌. 레퍼런스 퀄리티에 가장 가까움. 로봇팔이 "진짜로" 움직이진 않음. 이미지 제작 필요.
- **B. 실시간 3D (three.js / react-three-fiber)** — 붕봇·틀·붕어빵을 코드로 모델링(둥근 기본 도형 + 무광 파스텔 재질). 로봇팔이 단계별로 실제로 움직임. 의존성 추가(`three`, `@react-three/fiber`, `@react-three/drei`), 지연 로딩. 캐릭터 디테일은 레퍼런스보다 단순함.
- **추천: B + A 혼합** — 움직임이 핵심인 붕봇 장면(S2·S3·S4)은 B, 할매·할배·로고 같은 정적 캐릭터는 A(이미지 준비 전까지 SVG 대체).

모든 애니메이션은 `prefers-reduced-motion` 시 정지 이미지로 대체.

## 로봇 진행 mock

상태를 저장·타이머로 바꾸지 않고 **주문 시각 기준 경과 시간으로 계산**하는 순수 함수:

```ts
statusAt(createdAt, now) // 단계당 8초 → 약 40초 후 'ready'
```

새로고침해도 진행이 이어지고, 테스트가 쉬움. 실제 로봇 API 붙일 때 이 함수만 교체.

## 파일 구조

```
src/
  main.tsx, App.tsx              # 라우트 + 로그인 가드
  styles/tokens.css, global.css
  domain/menu.ts                  # 맛, 가격, 제한
  domain/order.ts                 # 타입, 합계, statusAt
  services/storage.ts             # localStorage 안전 래퍼
  services/authService.ts         # 임시 로그인/로그아웃
  services/orderService.ts        # 주문 생성/조회, 번호표 발급
  state/AuthContext.tsx, CartContext.tsx
  components/                     # FishBread, Bongbot, Grandparents, QtyStepper, BagBar, TabBar, StatusChip, ProgressSteps
  pages/                          # Login, Menu, Confirm, OrderStatus, History
```

라우트: `/login`, `/` (메뉴), `/confirm`, `/orders`, `/orders/:id`

## 작업 순서 (TDD)

1. Vite 프로젝트 생성, 토큰·폰트·글로벌 스타일
2. `domain/*` 테스트 먼저 → 구현 (합계, 제한, statusAt)
3. `services/*` 테스트 → 구현 (localStorage mock)
4. Context + 라우트 + 로그인 가드
5. 화면 S1 → S2 → S3 → S4 → S5 순
6. SVG 일러스트
7. 흐름 테스트: 로그인 → 담기 → 주문 → 내역에 표시
8. 브라우저 QA: 375px 모바일 + 데스크톱 스크린샷
